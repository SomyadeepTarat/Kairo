# M6 — Checkpointing and safe recovery

Scope: versioned kernel snapshots, checkpoint persistence, bounded attempt recovery,
committed-history projection, explicit uncertain-effect reconciliation and fault tests.
M5 was committed as b227eec before this implementation. M7 and later remain outside scope.

Core: `packages/core/src/kairo_core/checkpoints.py`, runtime resume/checkpoint paths,
`packages/core/src/kairo_core/orchestration/recovery.py`, queue/worker recovery,
checkpoint metadata and migration `migrations/versions/0003_checkpoints.py`.
Operator interface: `scripts/reconcile.py`, checkpoint/reconciliation HTTP routes.
Runnable input: `examples/scripted-job.json`. Learning: `docs/learning/m3-m6.md`.
Design: ADR 0010. No runtime dependency was added.

## Validation evidence

On macOS ARM64 / Python 3.13.4, the full `uv run --locked python scripts/check.py`
run with KAIRO_TEST_DOCKER=1 and the actual PostgreSQL test URL passed Ruff format/
lint, strict mypy (55 source files), and all 205 tests, with no skips. This includes
all actual Docker, migration, queue, killed-worker and recovery cases.

New cases cover confirmed writes across both crash/checkpoint windows, unknown
mutations, no-execution and known-result reconciliation, HTTP identity/schema
rejection, known-final completion without another model call, retry/deadline
exhaustion, retained workspace locks, and missing/redacted/invalid continuation, including workspace deletion during retry backoff.
The negative redaction test first failed because projection could overwrite its
marker; rejecting redacted checkpoints before projection fixed that gap. Earlier
annotation/import, formatting and test-type issues were also fixed before passing. A final guard regression distinguished a claimant that never
started from an execution whose existing workspace disappeared during backoff.

Migration upgrade/downgrade/drift checks passed on owned test schemas. The dedicated
local development database was upgraded through 0003. The actual enqueue/worker
CLI example completed run `27f659e7-201c-492a-94ed-65fa2f350ef7` in one attempt:
two confirmed tool calls, actual file content `hello from the sandbox`, DONE job
and COMPLETED run. Its workspace and history remain for inspection.

Locked offline sync and offline source/wheel builds passed. Wheel source was checked
against the tested kernel, sandbox, queue, worker, recovery and API modules. The
first metadata refresh attempted network resolution in the sandbox; offline locked
sync used the cached pinned build dependency successfully without changing versions.
Documentation links/whitespace and Git diff whitespace checks were reviewed.

No live worker/API service is left running. The local PostgreSQL container and
built sandbox image remain available. M6 implementation and validation are complete for the requested commit
`Add checkpointed recovery and reconciliation`; no M7 implementation is included.

Checkpoints reference persistent workspaces; they do not copy or roll back files.
Local workers require one shared host/root. Operator assertions are not independently
proven by the backend. Redacted, missing or invalid state blocks. Known terminal
runs are not resumed, and uncertain actions are not automatically repeated.
