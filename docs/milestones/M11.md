# M11 — Interactive dashboard

Implemented Next.js/TypeScript/Tailwind local dashboard: SQL aggregate overview,
task submission/explorer, run timeline/tools/checkpoints/trace/context, worker
heartbeats, role/dependency/handoff arena, durable approval controls and evaluation
outcomes/comparison charts. Python remains authoritative. New routes and optional
local service make controls execute real work, with no successful placeholders.

Study: `docs/learning/m11-m13.md`. Architecture: ADR 0015. Sequential review was
backend contracts → approvals/lease tests → UI → real browser actions → full gate.
An initial `scripts/platform.py` name shadowed Python's stdlib platform module; it
was renamed `scripts/serve.py`. A legacy API test expected POST runs to be absent;
it now verifies missing input is rejected by the implemented endpoint. Decorative
navigation icons were hidden from assistive technology after browser testing exposed
inaccurate accessible names. Frontend checks retain strict application typing.

Validation: service-enabled `uv run --locked python scripts/check.py` passed Ruff,
formatting, strict mypy (77 files), and 239 tests without skips. Frontend production
build and strict application type check passed. Two real Chrome Playwright tests
passed: queue → approval → actual write/read → terminal SSE/inspection, and mobile
layout without horizontal overflow. Screenshots were captured in temporary storage.
The running dashboard was opened in the in-app browser against actual persisted data.
Prettier formats the frontend for readable study; its role is tooling only.
No UI data was mocked. Scripted decisions in the browser test are explicitly labelled.
