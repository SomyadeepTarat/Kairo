# M2 — Tool system record

Scope: typed registry, file tools, command-executor contract, tool outcomes and
runtime integration. Implementation date: 2026-11-05. No sandbox or host command
executor was introduced. Design: `docs/decisions/0006-tool-system.md`.

Core paths: `packages/core/src/kairo_core/tools/registry.py`,
`packages/core/src/kairo_core/tools/files.py`,
`packages/core/src/kairo_core/tools/commands.py`,
`packages/core/src/kairo_core/tools/__init__.py`, plus models/runtime integration.
Tests: `tests/tools/test_tools.py`; previous kernel tests remain required.

The scripted integration actually writes and reads a temporary workspace file,
records both calls, supplies schemas/results to the model, and validates
WAITING_FOR_TOOL transitions. Additional tests cover strict validation, denied
permissions, unknown tools, protected paths, symlinks/hardlinks, literal search,
command-interface injection, duplicate registration, invalid outputs and timeout
cleanup. No inference or command sandbox is claimed.

Validation: Ruff format/lint, strict mypy (19 source files), all 156 tests and
`uv run --locked python scripts/demo_tools.py` passed on macOS ARM64 / Python 3.13.4.
The demo wrote 11 bytes and read back the exact content. Tests also demonstrate
that an uncertain partial write stops the run and cancellation joins/records an
active tool. Initial lint closure-binding and empty-list typing issues were fixed
before these checks passed. All study
material lives in `docs/learning/guide.md` without per-milestone study gates.
