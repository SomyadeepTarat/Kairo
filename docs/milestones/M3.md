  Ruff formatting/lint, strict mypy (38 source files), and all 169 tests passed,
  including all 9 real PostgreSQL integration tests, with no skips or warnings.
- `uv run --locked pytest tests/persistence --require-postgres -q`: passed all
  9 PostgreSQL cases after fixing migration default-schema/version-table alignment.
- `uv run --locked alembic upgrade head`: passed against the dedicated Compose DB.
- `scripts/demo_history.py`: COMPLETED with two real file-tool calls and 20 durable
  events. Run UUID: `2a1797b4-b5dd-4e41-bc9d-e3584fce54c7`.
- Separate-process `scripts/demo_history.py --inspect` read that history successfully.
- Two actual uvicorn process starts served the same persisted run and both tool
  records over loopback HTTP. Both temporary API processes were stopped afterward.
- Offline source/wheel builds passed. The wheel contains the core/API modules and
  both typing markers. Migrations/commands are intended to run from this checkout.
- Documentation links, authored-file whitespace and `git diff --check` were checked.

Test evidence includes migration upgrade/downgrade and metadata drift detection,
transaction rollback after injected event-insert failure, concurrent per-run event
ordering, terminal/stale-attempt rejection, recorded cancellation, redaction, API
recreation, and history retained after killing a real executing child process with
a partial filesystem write. That write remains STARTED/uncertain, not silently
retried or falsely marked completed.

Earlier failures were corrected before this result: missing SQLAlchemy asyncio
extra (greenlet), Python annotations/test module naming, and Alembic treating its
version table as an application table in isolated-schema drift checks. The local
Docker service was paused and later its PostgreSQL container was stopped; after
the user unpaused Docker, only Kairo's container was started and migrated.

Codex commands used `UV_CACHE_DIR=/private/tmp/kairo-uv-cache`. Ordinary developer
commands in README use uv's normal cache. PostgreSQL remains running with its named
volume so the demo can be inspected; no API server is left running. M3 changes are
uncommitted; the specifically requested intermediate M2 commit is preserved.

## Limits

This milestone records committed progress, not recovery. Interrupted tool effects
can remain uncertain and must not be repeated blindly. There is no durable queue,
worker lease, sandbox manager, checkpoint resume, live model adapter or dashboard.
The read-only API is for a trusted loopback environment. Learning is consolidated
without completion checklists, as requested; study understanding is not asserted.
